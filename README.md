# Daily Verse carousel

Every morning this repository prepares the day's Bible verse in **Tamil, English and German** for Christ the Living Petra Church and saves it as **drafts in Buffer**:

- a three-slide **carousel** (1080×1350) for the Facebook page and Instagram feed, and
- three short vertical **videos** (1080×1920), one each in Tamil, English and German, for Instagram Reels, Facebook Reels and YouTube Shorts. Each shows the verse with a slow zoom over soft background music and, when narration is on, reads it aloud.

Someone from the church reviews each draft in Buffer and approves it; nothing is published automatically.

| Slide | Text | Source |
|---|---|---|
| தமிழ் | பரிசுத்த வேதாகமம் | [tamil-bible.com](https://www.tamil-bible.com) |
| English | King James Version (public domain) | [DailyVerses.net](https://dailyverses.net) |
| Deutsch | Lutherbibel 1912 (gemeinfrei) | [DailyVerses.net](https://dailyverses.net/de) |

DailyVerses.net chooses the verse. The English and German texts come from its pages for that date, and the Tamil text of the same passage comes from tamil-bible.com. Slides and captions carry the title **Verse of the Day** (இன்றைய வசனம் · Vers des Tages, `label` in `church.json`) and no source credits: none of the sources requires one (see [Licensing](#licensing)). The church can also [pick its own verse](#your-own-verses-from-teams) for any day.

## Design

Each slide has a generated misty-mountain background, like the artwork on christ-livingpetra.de, and no two days look the same:

- **39 palettes**: 30 for weekdays (blues, purples, warm earth and gold tones, teal, neutrals and starry nights), 4 church greens that rotate on Sundays, and 5 for feast days: Christmas (24–26 Dec, with a star), New Year, Good Friday, Easter and Pentecost (dates calculated every year).
- Weekday palettes are shuffled each year and never repeat on consecutive days.
- Every day also varies the sky gradient and its angle, the sun or moon position and size, light rays, fog bands, and the mountain style (rolling, layered or alpine) and number of ridges.
- Re-rendering a date always gives the same picture, and a test checks that every palette keeps white text readable (WCAG 3:1 for large text).

Palettes live in `daily_verse/background.py`; the slide layout is `daily_verse/template.html`.

### Verse-matched backgrounds (optional)

With `BACKGROUNDS` = `ai`, each day gets one background painted for its verse by an Azure (Microsoft Foundry) image model: the English verse and its DailyVerses.net topics become a prompt for a calm nature or still-life scene, with strict rules (no people, no text, no depictions of God, a quiet middle for the text). The image is saved as `DD-scene.jpg`, shared by every language and format, and darkened automatically for readable white text. If Azure refuses or fails, that day uses the mountain background. The style is `image_style` in `church.json`.

Setup: deploy `gpt-image-2` in Microsoft Foundry, then add the secret `AZURE_OPENAI_KEY` and the variables `AZURE_OPENAI_ENDPOINT` (e.g. `https://<resource>.openai.azure.com`) and `AZURE_IMAGE_DEPLOYMENT` (the deployment name). Run **Actions → Preview narration** with *kind* = `backgrounds` to see sample images first.

## Music

By default each video gets an original instrumental composed in code (`daily_verse/music.py`): soft chords and sparse piano-like notes in a key and progression chosen per date. The church owns it outright, so YouTube's and Meta's copyright matching can never claim or mute a post, which does happen with "royalty-free" library tracks.

To use specific tracks instead, add audio files (mp3, m4a or wav) to `assets/music/`; the videos rotate through them by date, looping short tracks. Only add music the church is licensed to use on Facebook, Instagram and YouTube, and if a licence requires credit, add it to the captions in `church.json`.

## Read-aloud

Videos can read the verse aloud: the reference, then the verse, in a calm neural voice from [Azure AI Speech](https://learn.microsoft.com/azure/ai-services/speech-service/). Female and male voices alternate between the languages and swap every day; the music dips under the voice, and each word lights up on screen as it is read (follow-along), using the word timings Azure reports. Narrated Reels and Shorts are not labelled as AI-generated by default; set the variable `AI_LABEL` = `on` to label them on Instagram and YouTube (Meta asks for realistic AI audio to be disclosed and may label or limit undisclosed posts).

Voices and the speaking rate are in `church.json` (`voices`, `speaking_rate`); for example, use `ta-LK-SaranyaNeural` / `ta-LK-KumarNeural` for a Sri Lankan Tamil accent.

To set it up: create a free (F0) **Speech** resource in Azure, then add the secret `AZURE_SPEECH_KEY` (Key 1) and the variable `AZURE_SPEECH_REGION` (its location, e.g. `westeurope`). Run **Actions → Preview narration** to listen first; the videos appear as a download on the run page. When happy, add the variable `NARRATION` = `on` and new videos are narrated from the next morning.

## How it works

1. `.github/workflows/daily.yml` runs three times a day (06:15, 12:15 and 18:15 in summer); repeat runs skip days already done.
2. It renders slides and the video for the next days that DailyVerses.net has published (it publishes about two days ahead).
3. Everything is pushed to the [`media` branch](../../tree/media), which only keeps the last 14 days, so Buffer can download it.
4. For every day not yet in Buffer, it creates the drafts: the carousel per feed channel and each language's video per video channel (11 drafts a day), all with the publish time preset to 07:00.

Re-running is safe: each day's `DD.json` on the `media` branch records the drafts already created.

## Captions and church details

Each platform gets its own text, in Tamil, English and German:

- **Feed carousel** (Instagram, Facebook): the verse in all three languages, the service invitation, address and website, credits and hashtags.
- **Reels and Shorts**: one per language, with the caption, title and hashtags entirely in that language (`label`, `credits` and `language_hashtags` in `church.json`); YouTube descriptions add the weekly schedule and links.

Service times, address, links, invitation wording and hashtags live in [`church.json`](church.json). Edit that file (GitHub's web editor is fine) to change them; for example, add a German service to `schedule` and update `invitation` when German services start. Every entry needs `ta`, `en` and `de`.

## WhatsApp Status

WhatsApp has no official way to post a Status automatically (third-party tools that claim to do it connect like WhatsApp Web, which breaks WhatsApp's terms and can get the number banned). Instead, **https://franklinis.github.io/clp-daily-verse/** lists the day's videos with a **Share to Status** button: tap it, choose WhatsApp, then *My status*. **Copy caption** puts the label, reference and website on the clipboard for the Status text. The page is rebuilt by every run (`python -m daily_verse status-page`) and can be added to the phone's home screen.

## New background for a day

Don't like a day's picture? On GitHub open **Actions → New background → Run workflow**, enter the date (YYYY-MM-DD) and run it. It paints a new image for that verse, re-renders the day's slides and videos, and updates that day's drafts in Buffer in place: same time, same approval state. Posts already published are left alone.

## Your own verses (from Teams)

To choose a day's verse yourself, @mention **DailyVerse** in the church's Teams channel, one line per day:

```
@DailyVerse 20.10 Psalm 23:1
21.10 Römer 8,28 theme: hope, trust
```

- Dates can be written `20.10`, `20.10.2026`, `2026-10-20`, `20 Oct`, `tomorrow` or a weekday (`Monday`, `Montag`).
- References can be English or German, full or abbreviated (`Ps 23:1-3`, `1 Kor 13,4-7`). A colon means English verse numbers and a comma German (Luther) ones, which differ in many Psalms: `Psalm 51:10` and `Psalm 51,12` are the same verse. Up to 6 verses that fit on a slide.
- `theme:` words are optional; they steer the AI background.
- `list` shows the verses picked so far, `clear 20.10` gives a day back to DailyVerses.net and `help` explains it all.

DailyVerse answers in the channel within about a minute with the verse in all three languages, or with what's wrong. Picks are saved in [`custom-verses.csv`](custom-verses.csv), which can also be edited directly on GitHub. Days without a pick keep using DailyVerses.net.

Pick a verse at least 3 days ahead: the slides and drafts are made then, and DailyVerse posts again when they are in Buffer. A day that's already prepared switches to the new verse (new slides, videos and background, and its Buffer drafts are updated in place), but only until its posts are approved in Buffer; after that, move them back to drafts first. The English and German texts of picked verses come from public-domain copies bundled in `daily_verse/bible/` (King James Version and Lutherbibel 1912 from [eBible.org](https://ebible.org), rebuilt with `python tools/build_bible.py`), and the caption no longer credits DailyVerses.net.

The same can be done without Teams: **Actions → Set verse → Run workflow**, with the same lines.

## Days without posts

`skip_days` in `church.json` lists weekdays with no verse posts (currently Sunday). Those days are not prepared, drafted or shown on the Status page.

## Reviewing drafts

Open Buffer → **Drafts**. Check the slides and caption, then choose **Schedule** (keeps the 07:00 time) or edit the time first. Delete a draft to skip a day.

## Setup

1. In Buffer, go to **Settings → API** and create an API key.
2. In this repository, go to **Settings → Secrets and variables → Actions**:
   - **Secret** `BUFFER_API_KEY`: the key from step 1.
   - **Variable** `BUFFER_CHANNELS`: where the carousel goes, as comma-separated `channelId:service` pairs, for example `FACEBOOK_CHANNEL_ID:facebook,INSTAGRAM_CHANNEL_ID:instagram` (channel ids are in the URL when you open a channel in Buffer).
   - **Variable** `BUFFER_VIDEO_CHANNELS`: where the video goes, for example `FACEBOOK_CHANNEL_ID:facebook,INSTAGRAM_CHANNEL_ID:instagram,YOUTUBE_CHANNEL_ID:youtube`.
   - Optional **variable** `POST_TIME`: preset publish time, default `07:00` (Europe/Berlin).
3. Run the workflow once from **Actions → Daily verse drafts → Run workflow**.

Without the API key the workflow still renders and publishes everything, but creates no drafts.

### Teams (optional, for picking verses)

1. **GitHub token**: on GitHub, **Settings → Developer settings → Fine-grained tokens → Generate new token**. Repository access: only `clp-daily-verse`; permissions: **Actions: Read and write**. Copy the token.
2. **Azure Logic App** (Consumption plan; a few cents a month): create one in the Azure portal, open **Logic app code view**, paste [`teams/logic-app.json`](teams/logic-app.json), replace `PASTE-THE-GITHUB-TOKEN-HERE` with the token and save. Open the designer and copy the **HTTP URL** of the trigger.
3. **Outgoing webhook**: in Teams, open the church team → **⋯ → Manage team → Apps → Create an outgoing webhook**. Name `DailyVerse`, callback URL = the Logic App URL. (Only works in standard channels.)
4. **Answers in the channel**: in the same channel, **⋯ → Workflows → Send webhook alerts to a channel**, pick the team and channel, and copy the webhook URL. Add it here as the **secret** `TEAMS_WEBHOOK_URL`.

The Logic App URL contains its own access key, so keep it as private as a password; anyone with it could pick verses (which still need approval in Buffer).

Buffer's free plan allows 10 scheduled posts **per channel at a time**; a slot frees up as soon as a post publishes, so there is no monthly limit. Facebook and Instagram each get four posts a day (the carousel and three Reels) and YouTube three, so drafts can be approved up to two days ahead.

## Run locally

Requires Python 3.11+ and Google Chrome.

```bash
pip install -r requirements.txt
python3 -m daily_verse render --start 2026-10-15 --days 1
```

Slides and the video are written to `images/`. Use `--force` to re-render a day after changing the design in `daily_verse/template.html`. Tests: `pip install pytest && pytest`.
